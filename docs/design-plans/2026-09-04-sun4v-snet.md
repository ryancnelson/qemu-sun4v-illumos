# sun4v SNET Ethernet device

**Status:** accepted for implementation

## Goal

Replace the successful Ethernet-over-hsimd experiment with a real guest MAC
driver and a QEMU network frontend. Packets must no longer traverse disk
strategy, labels, or block-I/O queues.

## Existing hardware contract

OpenSPARC q.bin already implements `SNET_READ` (`0xf2`) and `SNET_WRITE`
(`0xf3`). Each hypercall copies aligned 64-bit words between guest real memory
and one fixed physical address. The address is therefore a FIFO data port, not
a RAM window. The current MD assigns it physical address `0xfff0c2c050` and
interrupt `0x3f`.

## Record format

The FIFO carries one header word followed by a padded Ethernet frame:

```text
63                    48 47       32 31                       0
+-----------------------+-----------+--------------------------+
| magic 0x534e ("SN")   | version 1 | frame length in bytes    |
+-----------------------+-----------+--------------------------+
| Ethernet bytes, padded with zeroes to an eight-byte boundary  |
+---------------------------------------------------------------+
```

A zero header means that no receive frame is queued. Lengths outside 14..1518
or a bad magic/version reset the partial record and increment an error counter.
The byte stream is network byte order, independent of host endianness.

## QEMU side

`sun4v-snet` is a QEMU NIC frontend backed by the normal `NICState` API. It
maps an eight-byte big-endian MMIO region at the MD address. Writes assemble a
record and submit complete frames to the configured QEMU netdev. Incoming
frames are queued as records and returned one word per MMIO read.

The first implementation has a bounded receive queue and exposes counters
through QEMU tracing. It deliberately does not pretend the current sun4v IOB
can deliver the SNET interrupt correctly.

## illumos side

The `snet` GLDv3 driver binds to `net-virtual-device`. Transmit writes a header
and the padded frame through hypercall `0xf3`. A cyclic callback polls one
header word through `0xf2`; when a frame is present it reads the remaining
words and calls `mac_rx()`. Buffers passed to q.bin are eight-byte aligned and
converted with `va_to_pa()`.

Polling is an explicit bootstrap choice. After QEMU sun4v interrupt delivery
is proven, the same framing and MAC surface remain while receive moves to an
interrupt handler.

## Safety and limits

- Ethernet MTU is 1500; VLAN-tagged frames up to 1518 bytes are accepted.
- Queue memory and partial records are bounded.
- Malformed records are dropped rather than copied into an undersized buffer.
- No disk device, disk image, or hsimd strategy path participates.
- The driver is experimental and must not become a release default until an
  OpenIndiana guest proves attach, TX, RX, ARP, ICMP, and sustained traffic.

## Acceptance gates

1. Protocol model rejects malformed and truncated records.
2. The QEMU frontend builds against the pinned Murayama QEMU tree.
3. The illumos module builds against pinned illumos `31d3d510` headers.
4. Guest `dladm show-link` reports the new MAC.
5. QEMU user networking answers guest ARP and ICMP.
6. A 64 KiB TCP round trip matches byte-for-byte without hsimd traffic.
