# Mica opt-in CMD646 compatibility experiment design review
Design is internally coherent as an explicitly experimental B134 compatibility model, not a manufacturer-proven latch contract. Exact patch/build acceptance pending. Review workspace: work/maestro-sun4u-001/cmd646-compat-experiment/mica-review. No implementation, guest or deployment performed.

Transition constraints: maintain live bits independently from pending bits in PCI config. Low-to-high sets both; high-to-low clears live only; W1C clears selected pending mirrors without altering live. Output ORs unblocked LIVE channels, so W1C while input high leaves output asserted, whereas STATUS falling input deasserts output even with retained pending. Repeated high after W1C cannot re-latch until a real low-to-high. Block writes neither acknowledge pending (unless W1C bits also explicitly written) nor create edges. Existing ack-only patch806842be34741f187d2aac4d431db7e27a52785124f3bbc6e7144047e4dfcbe6 is declared dependency; default unchanged means relative to that dependency, not pristine8.2.2.

Important tests: both channels independently and simultaneously; live0/pending1 and live1/pending0 are LEGAL states, not migration corruption. W1C-high and repeated-high must retain live1/pending0 until fall-rise. Both PCI and I/O ack/block paths must agree. Check PCI output follows live, not pending, after STATUS, W1C and migration. Do not reuse earlier tentative IRQ-hold test as a pass requirement.

Reset: call actual ide_bus_reset for both buses before clearing compatibility live/pending; explicitly recompute low output after clearing. Preserve nonindicator config bits. Test real callback ordering and actual reset effects; prior GPIO-only reset stub cannot prove reset correctness. Disabled branch must retain existing reset behavior.

Migration design constraints: embed PCIIDEState at offset0 in derived CMD646State and set exact instance_size. Preserve complete base descriptor metadata/fields and default serialization; avoid nesting the base as a new wire field. Base v8.2.2 VMStateDescription is name ide, version3, minimum0, with PCI device, BMDMA, buses and drives; base post_load repairs DMA retry state. Chain that callback once and propagate errors. Copying complete descriptor then overriding only necessary hooks/subsection is less error-prone than partial reconstruction. No mutation of globally shared vmstate_ide_pci.

Live-only optional subsection suffices because pending mirrors already migrate in PCI config. Subsection must be emitted whenever opt-in is enabled, INCLUDING all-zero live state; needed() must not depend on live!=0. Local subsection-presence sentinel reset in pre_load on EVERY load, then set only when actually parsed; no inference from zero live value or property. Reject enabled/missing and disabled/present after subsections load. Reject illegal live bits and inconsistent pending mirrors for opt-in; do not require live==pending. Recompute opt-in output only after validation and chained base post_load. Disabled state must not gain validation/recomputation that changes previously accepted streams/output. Verify repeated loads so old presence sentinel cannot mask missing subsection.

Default wire equivalence needs actual serialization comparison and base-to-new default roundtrip, not only VMState field-name checks. Test optin-on roundtrip for all legal live/pending combinations plus block masks; property mismatch both directions; malformed live/mirror bits; absent subsection with live0; legacy version boundaries supported by base; unchanged default callback behavior. Subsection load ordering must be confirmed from exact8.2.2 migration engine or actual save/load fixture before relying on parent post_load presence validation. No claim this v8.2.2 build reconstructs Ubuntu pinned902dc binary.

Primary source checked: https://raw.githubusercontent.com/qemu/qemu/v8.2.2/hw/ide/pci.c lines509-537 (base postload/descriptor),563-573 (BMDMA wraps bus IRQ). Exact local cmd646 baseline still uses vmstate_ide_pci, parent TYPE_PCI_IDE. Full migration engine source and exact candidate remain pending, so these are design constraints, not a migration implementation approval.
